1. Overview

Table Tennis Central Club is a one-page website for a community table tennis club. It introduces the club, describes three programs (League Nights, Beginner Clinics and the Junior Academy), lets visitors request a free trial session, and lists contact details and opening hours.

The site is built on Grayscale 7.0.6, a free Bootstrap 5 theme by Start Bootstrap released under the MIT License. I kept the template's Bootstrap grid, navigation behaviour and section layout, and replaced or reworked everything else: content, artwork, colour theme, the sign-up form, and every accessibility and validation problem the original shipped with.

Problems I ran into along the way

My own CSS broke the mobile layout

I gave the About image max-width: 900px to stop it growing too large on desktop. Because custom.css loads after Bootstrap, this replaced Bootstrap's .img-fluid { max-width: 100% }, and on a 390px phone the image became 812px wide and the whole page scrolled sideways. The fix was width: 100%; max-width: 900px;. I then checked six widths from 360px to 1920px and none of them overflow.

WAVE still found one contrast error after my first pass

The visually hidden “Contact” heading I added inherited Bootstrap's dark body colour (#212529) inside the black contact section, so its contrast was 1.4:1. Nobody sees it, but a screen reader user with a custom stylesheet could. I made it white. I also gave every gradient section a solid background-color fallback, so text stays readable if the background image fails and checkers can measure the real contrast.

A specificity clash turned an icon the wrong colour

My .footer a rule (yellow links) was more specific than .back-to-top, so the back-to-top arrow turned yellow on red. I raised the selector to .footer .back-to-top so the arrow is white as intended.

5. Responsive Design

The template's Bootstrap grid already handled the main column changes, and I kept it. On phones the menu collapses behind a “Menu” button, each program becomes an image stacked above its text, and the three contact cards stack. From 992px up the navigation spreads out and programs sit beside their images. My additions had to respect that system. The title uses clamp() instead of fixed breakpoints, and nothing in custom.css sets a fixed width without a max-width or % fallback.

.masthead h1 {
  max-width: 14ch;
  font-size: clamp(2.2rem, 7vw, 5.5rem);
  line-height: 1.1;
  letter-spacing: 0.35rem;
}

.about-image {
  width: 100%;
  max-width: 900px;
}

6. Styling

Instead of editing Bootstrap's 11,000-line stylesheet, all my styling lives in a separate css/custom.css that loads after it. A single block of CSS custom properties defines the palette, and every rule reads from those variables. Bootstrap 5 also exposes its own button colours as variables, so I re-themed the buttons by overriding those variables rather than rewriting the button rules.

7. Four Extras

None of these four features exist in the original template. I designed and coded all of them.

1 Working, accessible sign-up form (JavaScript)

The template's form needs a paid service and a token, so out of the box it does nothing. I removed that dependency and wrote js/signup.js. The form checks for an empty or malformed email, marks the field with aria-invalid, moves focus back to it, and writes the message into a role="status" region so screen readers announce it. A valid address shows a confirmation and clears the field.

function handleSignup(event) {
  event.preventDefault();
  const input = document.getElementById("emailAddress");
  const status = document.getElementById("signupStatus");
  const email = input.value.trim();

  if (!EMAIL_PATTERN.test(email)) {
    input.setAttribute("aria-invalid", "true");
    showStatus(status, "That email address does not look right. Try name@example.com.", "is-error");
    input.focus();
    return;
  }

  input.removeAttribute("aria-invalid");
  showStatus(status, "Thanks! This week's open times are on their way to " + email + ".", "is-success");
  event.target.reset();
}
<label class="signup-label" for="emailAddress">Email address</label>
<input class="form-control" id="emailAddress" type="email" autocomplete="email"
       required aria-describedby="signupStatus">
<p class="signup-status" id="signupStatus" role="status" aria-live="polite"></p>

2 Skip to Main Content link and landmark structure

The template has a fixed navigation bar that keyboard users must tab through on every visit. I added a skip link that stays hidden off screen until it receives focus, and wrapped the page content in a <main> landmark for it to jump to. That same landmark fixed aXe's two landmark violations.

.skip-link {
  position: absolute;
  top: -100px;
  left: 16px;
  z-index: 2000;
  transition: top 0.25s ease-in-out;
}

.skip-link:focus {
  top: 0;
  outline: 3px solid var(--tt-red);
}

3 Back-to-top button revealed on scroll (JavaScript)

On a long one-page site, a button in the corner saves scrolling back up. It stays invisible while the visitor is near the top, then fades and slides in after 600px of scrolling. When hidden it uses visibility: hidden, so keyboard users never tab onto an invisible control. It sits inside the footer landmark and has an aria-label.

function toggleBackToTop() {
  const button = document.getElementById("backToTop");
  button.classList.toggle("is-visible", window.scrollY > 600);
}

document.addEventListener("scroll", toggleBackToTop);
.footer .back-to-top {
  position: fixed;
  right: 20px;
  bottom: 20px;
  opacity: 0;
  visibility: hidden;
  transform: translateY(12px);
  transition: opacity var(--tt-ease), transform var(--tt-ease), visibility var(--tt-ease);
}

.back-to-top.is-visible {
  opacity: 1;
  visibility: visible;
  transform: translateY(0);
}

4 Motion design that respects reduced-motion settings

Program cards lift and cast a shadow on hover, and they do the same on :focus-within so keyboard users get the effect too. Buttons rise slightly and links change colour, all with transitions. Some people get dizzy or nauseous from on-screen motion, so a prefers-reduced-motion media query turns every transition and transform off for visitors who have asked their operating system for less motion.

.program-card {
  transition: transform var(--tt-ease), box-shadow var(--tt-ease);
}

.program-card:hover,
.program-card:focus-within {
  transform: translateY(-6px);
  box-shadow: 0 18px 30px rgba(11, 61, 46, 0.3);
}

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }

  .program-card:hover,
  .program-card:focus-within,
  .btn-primary:hover {
    transform: none;
  }
}
